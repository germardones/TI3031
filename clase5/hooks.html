useState & useEffect

Los dos hooks más importantes de React. Uno guarda información que puede cambiar; el otro sincroniza tu componente con el mundo exterior.

1. useState — memoria del componente

En React, una variable normal no provoca que la pantalla se actualice cuando cambia. Para que React "se entere" de un cambio y redibuje la interfaz necesitas declarar esa variable como estado con useState.

❌ Variable normal
function Contador() {
  let n = 0; // React no la observa

  return (
    <button onClick={() => n++}>
      Clics: {n} // nunca cambia
    </button>
  );
}

El valor cambia en memoria, pero la pantalla no se actualiza.

✅ useState
function Contador() {
  const [n, setN] = useState(0);

  return (
    <button onClick={() => setN(n + 1)}>
      Clics: {n} // se actualiza
    </button>
  );
}

Cada llamada a setN dispara un re-render automático.

Anatomía de useState

const [valor, setValor] = useState(valorInicial);

valor

El dato actual. Lo lees directamente en el JSX o en funciones.

setValor

La función que actualiza el estado. Llamarla provoca un re-render.

valorInicial

Solo se usa la primera vez que el componente se monta. Puede ser cualquier tipo.

Ciclo de re-render

🖱️

Evento

click, input, etc.

→

📞

setValor(nuevo)

actualizas el estado

→

⚙️

React re-renderiza

ejecuta la función del componente

→

🖥️

Pantalla actualizada

el nuevo valor aparece

Ejemplos prácticos

Estado booleano (toggle)
const [abierto, setAbierto] = useState(false);

<button onClick={() => setAbierto(!abierto)}>
  {abierto ? "Cerrar" : "Abrir"}
</button>
{abierto && <div>Contenido</div>}
Estado de un input
const [nombre, setNombre] = useState("");

<input
  value={nombre}
  onChange={(e) => setNombre(e.target.value)}
/>
<p>Hola, {nombre}</p>
Estado con objeto
const [usuario, setUsuario] = useState({
  nombre: "", edad: 0
});

// Siempre spread para no perder otros campos
setUsuario({ ...usuario, nombre: "Ana" });
Estado con array
const [items, setItems] = useState([]);

// Agregar sin mutar el array original
setItems([...items, nuevoItem]);

// Eliminar por id
setItems(items.filter((i) => i.id !== id));

Regla importante

Nunca modifiques el estado directamente (estado.campo = valor). Siempre usa el setter (setEstado(...)). React necesita detectar el cambio para saber que tiene que re-renderizar.

2. useEffect — sincronizar con el exterior

El renderizado de React es puro: tomar estado → devolver JSX, sin efectos secundarios. Pero las apps reales los necesitan. useEffect es el lugar seguro para ejecutarlos.

Ejemplos de efectos: pedir datos a una API, guardar en localStorage, suscribirse a un evento del DOM, iniciar un temporizador.

Sintaxis

useEffect(() => {
  // código del efecto

  return () => {
    // limpieza (opcional)
  };
}, [/* dependencias */]);

Función del efecto

Se ejecuta después de que React pinta el componente. Aquí va tu lógica asíncrona o con efectos secundarios.

Función de limpieza

Opcional. Se ejecuta antes de que el componente se desmonte o antes de volver a correr el efecto. Cancela suscripciones y timers aquí.

El array de dependencias

El segundo argumento controla cuándo se ejecuta el efecto. Es la parte más importante (y más confusa) de useEffect.

Segundo argumento ¿Cuándo se ejecuta? Caso de uso típico
[] — array vacío Solo al montar el componente (una vez) Cargar datos iniciales de una API
[dep1, dep2] — con valores Al montar y cada vez que alguna dep cambia Re-buscar datos cuando cambia un filtro
sin argumento En cada re-render (generalmente no es lo que quieres) Raro; puede causar bucles infinitos
Solo al montar [ ]
useEffect(() => {
  cargarDatos();
}, []); // una vez

Equivale al antiguo componentDidMount.

Reactivo a búsqueda
useEffect(() => {
  buscar(query);
}, [query]);
// re-busca si query cambia

Se dispara cada vez que query tiene un nuevo valor.

Con limpieza
useEffect(() => {
  const id = setInterval(
    tick, 1000
  );
  return () =>
    clearInterval(id);
}, []);

La limpieza cancela el timer cuando el componente se desmonta.

Trampa frecuente: bucle infinito

// ❌ MAL: setDatos cambia datos → re-render → efecto corre → setDatos...
useEffect(() => {
  setDatos([...datos, extra]);
}); // sin array de dependencias

Si el efecto actualiza un estado que está en sus dependencias sin control, crea un bucle infinito. Añade [] o revisa bien qué dependencias realmente necesitas.

3. Trabajando juntos

La combinación más común: useState guarda los datos, useEffect los carga al montar el componente. El siguiente patrón lo verás en casi toda app React real.

Patrón: cargar datos al montar
import { useState, useEffect } from "react";

function ListaUsuarios() {
  // 3 estados: datos, carga y error
  const [usuarios, setUsuarios] = useState([]);
  const [cargando, setCargando] = useState(true);
  const [error, setError] = useState(null);

  // Efecto: pedir al montar ([] = una sola vez)
  useEffect(() => {
    async function cargar() {
      try {
        const res = await fetch("/api/usuarios");
        const json = await res.json();
        setUsuarios(json);
      } catch (e) {
        setError(e.message);
      } finally {
        setCargando(false);
      }
    }
    cargar();
  }, []);

  if (cargando) return <p>Cargando...</p>;
  if (error) return <p>Error: {error}</p>;

  return (
    <ul>
      {usuarios.map((u) => (
        <li key={u.id}>{u.nombre}</li>
      ))}
    </ul>
  );
}
Patrón: reaccionar a un filtro

Cuando el usuario escribe en un campo de búsqueda quieres re-buscar automáticamente. El término de búsqueda entra en el array de dependencias.

const [query, setQuery] = useState("");
const [resultados, setResultados] = useState([]);

useEffect(() => {
  if (!query) { setResultados([]); return; }
  buscarEnAPI(query).then(setResultados);
}, [query]); // se ejecuta cada vez que query cambia

return (
  <>
    <input value={query} onChange={(e) => setQuery(e.target.value)} />
    {resultados.map((r) => <p key={r.id}>{r.titulo}</p>)}
  </>
);

🧠

useState

Guarda información que puede cambiar. Cada cambio provoca un re-render. Es la memoria del componente.

🔌

useEffect

Sincroniza el componente con el exterior. Se ejecuta después del render y controla cuándo correr con el array de dependencias.
